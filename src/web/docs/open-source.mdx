# Open source

The forwarder is published as a set of npm packages and a CLI.

Repository: [github.com/logtura/logtura](https://github.com/logtura/logtura)

## Packages

| Package                                    | Role                                                       |
| ------------------------------------------ | ---------------------------------------------------------- |
| `@logtura/core`                            | Driver contracts, renderer, Vector topology types          |
| `@logtura/cli`                             | `logtura validate` / `bundle` / `install-zip`              |
| `@logtura/driver-cloudflare-worker-tail`   | Cloudflare Workers tail                                    |
| `@logtura/driver-cloudflare-ai-gateway`    | Cloudflare AI Gateway logs                                 |
| `@logtura/driver-fly-log-tail`             | Fly NATS log stream                                        |
| `@logtura/driver-railway-logs`             | Railway logs                                               |
| `@logtura/driver-supabase-edge-logs`       | Supabase edge function logs                                |
| `@logtura/driver-vercel-logs`              | Vercel log drain receiver                                  |
| `@logtura/destination-slack`               | Slack webhook                                              |
| `@logtura/destination-webhook`             | Generic HTTP POST                                          |
| `@logtura/destination-datadog-metrics`     | Datadog Metrics API                                        |
| `@logtura/destination-prometheus-remote-write` | Prometheus remote-write                                |
| `@logtura/custom-vector`                   | Pass-through escape hatch for any Vector source or sink    |

## CLI

The CLI reads a `logtura.yaml` file and produces a Vector bundle.

### Example config

```yaml
sources:
  workers:
    provider: cloudflare-worker-tail
    account_id: env:CLOUDFLARE_ACCOUNT_ID
    api_token: env:CLOUDFLARE_API_TOKEN
    scripts:
      - dirtsignal
      - ipogrid

sinks:
  slack:
    type: slack
    webhook_url: env:SLACK_WEBHOOK_URL
    channel: "#alerts"

monitors:
  - name: worker-errors
    filter:
      - errors
      - rollup:
          window_secs: 30
          group_by: [script]
          max_samples: 5
    sinks: [slack]

metrics: none
```

### Validate

```bash
CLOUDFLARE_ACCOUNT_ID=acct \
CLOUDFLARE_API_TOKEN=token \
SLACK_WEBHOOK_URL=https://hooks.slack.com/... \
logtura validate -c logtura.yaml
```

`validate` checks the config against driver schemas, renders the Vector topology, and runs `vector validate` against it. Exit code is non-zero on any error.

### Bundle

```bash
logtura bundle -c logtura.yaml -o dist/logtura-forwarder
```

Produces a directory with `vector.yaml`, a `Dockerfile`, and the driver helper binaries the topology needs.

### Install-zip

```bash
logtura install-zip -c logtura.yaml -o logtura-forwarder.tgz
```

Same contents as `bundle`, packed into a tarball suitable for copying to a server.

## Running the bundle

```bash
docker build -t logtura-forwarder dist/logtura-forwarder
docker run --rm \
  -e CLOUDFLARE_ACCOUNT_ID=acct \
  -e CLOUDFLARE_API_TOKEN=token \
  -e SLACK_WEBHOOK_URL=https://hooks.slack.com/... \
  logtura-forwarder
```

Set `LOGTURA_HEARTBEAT_URL` if you want the bundle to report to the hosted control plane. Leave it unset for a fully detached run.

## Writing a driver

A driver implements the `ProviderDriver<Credentials>` interface from `@logtura/core`. The minimum surface is:

```ts
export const myDriver: ProviderDriver<MyCreds> = {
  id: "my-driver",
  displayName: "My provider",
  sourceLabel: "Service",
  capabilities: { selection: "list" },

  async verifyCredentials(creds) { /* ... */ },
  async checkCredentialFreshness(creds) { /* ... */ },
  async discoverSources({ credentials }) { /* returns DiscoveredSource[] */ },
  generatePipeline({ connection, selection }) {
    return {
      components: [/* VectorComponent[] */],
      manifest: [/* helper binaries this driver needs */],
    };
  },
};
```

Register it in `packages/cli/src/registry.ts` and in the control plane's driver registry. Driver packages must not depend on the control plane.
