# Architecture

Logtura has two parts:

1. A hosted control plane at `logtura.com`. It stores connection metadata, source inventories, monitor and destination definitions, and deployment state.
2. An open-source forwarder built on Vector. It runs in infrastructure you control and ships logs from providers to destinations.

The forwarder runs on your own machine, Fly app, container, or VM. Log payloads pass from the provider, through the forwarder, to the destination. They do not pass through `logtura.com`.

## Components

| Component                        | Where it runs                  | What it holds                                                                 |
| -------------------------------- | ------------------------------ | ----------------------------------------------------------------------------- |
| Control plane API                | Cloudflare Workers + D1        | Accounts, encrypted credentials, source lists, monitor/destination configs    |
| Web UI                           | Cloudflare Workers (static)    | React app served from the same Worker                                         |
| Forwarder                        | Your Fly app / VM / container  | Vector binary, generated config, driver helpers (e.g. `logtura-cf-tail`)      |
| Heartbeat + metrics endpoint     | Control plane                  | Liveness pings and per-source event counters posted by the forwarder          |

## Data flow

```
provider API ──► forwarder (Vector) ──► destination (Slack, Datadog, S3, …)
                       │
                       └─► control plane: heartbeat, event counters
```

Log content stays on the left-to-right arrow. The downward arrow carries only operational signals:

- Forwarder liveness timestamp
- Per-source event counts in 60-second buckets
- Vector internal metrics (component errors, buffer depth)
- Deploy job status

## Source kinds

Each source kind has a driver package under `packages/`:

| Driver                          | Transport                                  | Selection model     |
| ------------------------------- | ------------------------------------------ | ------------------- |
| `cloudflare-worker-tail`        | Workers Tail API (per-script multiplex)    | List of scripts     |
| `cloudflare-ai-gateway`         | AI Gateway logs API                        | List of gateways    |
| `fly-log-tail`                  | Fly NATS log stream                        | List of apps        |
| `railway-logs`                  | Railway GraphQL log subscription           | List of services    |
| `supabase-edge-logs`            | Supabase logs HTTP poll                    | List of projects    |
| `vercel-logs`                   | Vercel Log Drains receiver                 | All-of-team         |
| `custom-vector`                 | Any Vector source                          | Pass-through        |

## Destination kinds

| Driver                          | Sink type                            |
| ------------------------------- | ------------------------------------ |
| `slack`                         | Slack incoming webhook               |
| `webhook`                       | Generic HTTP POST                    |
| `datadog-metrics`               | Datadog Metrics API                  |
| `prometheus-remote-write`       | Prometheus remote-write              |
| `custom-vector`                 | Any Vector sink                      |
